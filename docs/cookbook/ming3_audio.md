# Ming 3 audio

Ming 3 audio supports transcription, audio chat, and speech synthesis with an
optional reference recording and transcript. The pipeline uses a Whisper audio
encoder, a tensor-parallel Ling V3 thinker, and a continuous-latent speech decoder.

## Run locally

Use a local checkpoint directory containing the thinker shards and the complete
`talker/` directory. The default placement requires two GPUs: the thinker uses
TP 2, the audio encoder runs on GPU 0, and speech synthesis runs on GPU 1.

```bash
CUDA_VISIBLE_DEVICES=0,1 sgl-omni serve \
  --model-path "$MODEL_PATH" --host 127.0.0.1 --port 8091
```

The validated runtime uses Transformers 5.12.1 and SGLang 0.5.20 source revision
`94602c9c2`. An older 0.5.20 wheel on the validation server lacked the scheduler
metrics interface required by this checkout. Use the matching SGLang source
when reproducing these results.

Transcribe a recording:

```bash
curl http://127.0.0.1:8091/v1/audio/transcriptions \
  -F model=inclusionAI/Ming-3.0-audio-flash \
  -F file=@input.wav -F temperature=0
```

The transcription endpoint removes the language prefix from the model's
language-and-transcript response. Chat requests preserve the generated answer.
Audio chat accepts `input_audio`, `audio_url`, and the top-level `audios` input.
Request `modalities: ["text", "audio"]` to synthesize the thinker's answer.

Synthesize with a reference voice:

```python
import base64
from pathlib import Path

import requests

reference = base64.b64encode(Path("reference.wav").read_bytes()).decode()
response = requests.post(
    "http://127.0.0.1:8091/v1/audio/speech",
    json={
        "model": "inclusionAI/Ming-3.0-audio-flash",
        "input": "Get the trust fund to the bank early.",
        "ref_audio": f"data:audio/wav;base64,{reference}",
        "ref_text": "The exact transcript of the reference recording.",
        "response_format": "wav",
        "seed": 123,
    },
    timeout=180,
)
response.raise_for_status()
Path("speech.wav").write_bytes(response.content)
```

Speech is generated at 44.1 kHz. The pipeline returns the complete waveform;
incremental speech output is not implemented. Requests are processed serially
within the speech synthesis stage. The reference transcript should match the
reference recording.

## Correctness baseline

Validation pins model revision `354b5d98e2de85e4092575c92e699eda5fa78ab9` and
SeedTTS dataset revision `27f4c1adee83b5b29b7c4b375f6b976324bda308`. This dataset's
English split contains **1088** entries. WER uses the existing benchmark's
Whisper English normalization and corpus-level word counts, including every
successful sample and reporting failures separately.

The eager BF16 TP 2 ASR baseline on two H200 GPUs completed all 1088 entries
without failures, with **1.165% WER**. CUDA graphs and asynchronous decode were
disabled for this baseline. Performance comparisons require isolated runs;
concurrent speech synthesis and scoring were used during correctness evaluation.

The eager TTS baseline also completed all 1088 entries without failures, with
**1.114% WER**. Synthesis used seed 123 and each entry's reference recording and
transcript. Scoring used Qwen3-ASR-1.7B revision
7278e1e70fe206f11671096ffdd38061171dd6e5 with English forced and greedy decoding.
The first 373 samples exercised the speech HTTP endpoint; the remaining samples
used the same speech generator directly on two GPUs after releasing the thinker.

The audio encoder unit test uses fixed outputs generated by the checkpoint's
reference implementation with a small deterministic configuration. Other unit
tests check waveform amplitude, stereo downmixing, and resampling against
analytic signals. Tests and implementation changes are maintained in separate
commits.

```bash
python -m pytest tests/unit_test/ming3_audio -q
python -m benchmarks.eval.benchmark_asr_seedtts \
  --port 8091 --model-path inclusionAI/Ming-3.0-audio-flash \
  --model-revision 354b5d98e2de85e4092575c92e699eda5fa78ab9 \
  --dataset-revision 27f4c1adee83b5b29b7c4b375f6b976324bda308 \
  --lang en --concurrencies 4 --repeats 1 --warmup \
  --output asr_seedtts_results.json
```

## Optimizations and parity

The default enables CUDA graph replay for the speech decoder's flow matching,
aggregator, and stop head. Random noise is generated outside capture using the
request seed. Audio encoding, the talker's language model, and VAE decoding
remain eager. The encoder-to-thinker transfer still passes through host memory,
and speech generation still synchronizes on its stop decision each step.

All 1088 speech waveforms match the eager baseline exactly when the same WAV
serialization is used. An initial independent scoring pass measured **1.122%
WER** because its standalone WAV writer differed from the HTTP writer used for
the baseline's first 373 samples by at most two PCM16 levels. Repeating those
373 through the same HTTP endpoint removed every waveform difference; the other
715 were already identical. The full eager correctness checkpoint is preserved
in the local tag `ming3-audio-eager-baseline`.

A paired benchmark on one H200 measured 100 consecutive SeedTTS entries after
one warmup pair, with no other GPU work on that device. Each pair used the same
loaded model, input, reference, and seed. Mean complete synthesis time, including
reference encoding and VAE decoding but excluding HTTP, fell from **0.982 s** to
**0.338 s** (**2.91x**). Median times were 0.910 s and 0.323 s. All 101 pairs,
including warmup, produced bitwise-identical floating-point waveforms. This is a
single-request benchmark, not a concurrent serving throughput measurement.

Thinker decode CUDA graphs and the shared asynchronous scheduler were also tested
on all 1088 ASR inputs. They produced **1.188% WER**, with three normalized
transcripts differing from the eager baseline's **1.165%**. These options remain
disabled by default because output parity has not been established.

To reproduce the eager baseline, write a local JSON configuration and pass its
path to `sgl-omni serve --config`:

```json
{
  "config_cls": "Ming3AudioPipelineConfig",
  "model_path": "/path/to/local/checkpoint",
  "stages": {
    "talker": {"factory": {"enable_cuda_graph": false}}
  }
}
```

To investigate the optional thinker optimization, set
`stages.thinker.factory.enable_async_decode` to `true`,
`stages.thinker.engine.disable_cuda_graph` to `false`, and
`stages.thinker.engine.cuda_graph_max_bs` to `8`. The evaluated configuration also
used `max_total_tokens: 65536` and `cuda_graph_backend_prefill: "disabled"` under
`stages.thinker.engine`. These settings do not enable prefill graph capture.

The model's 22 unit tests pass, including CUDA graph parity across successive
requests and early stopping. The related Ming suites report 438 passed and two
pre-existing failures in `ming_omni/test_tp.py`: their mocked torch profiler lacks
`supported_activities`. Both failures were reproduced on the unchanged base
commit. All repository pre-commit checks pass. Text chat, speech synthesis,
transcription, and the model's supplied speech-question example were exercised
through the HTTP API.
